# Kat local Reading Room

This is a same-origin browser client of the **single-process** M2 archive, not a remote service. It uses the selected Reading Room v2 layout without its fictional sample data. The workspace password is distinct from any model-provider connection. Repository tests and examples use only synthetic accounts/content; they do not establish permission to access an existing private archive or make a live provider request. Reading Room is the single supported chat surface.

For a **new, owned, standalone local instance**, from the repository root (with `.venv-swiss` installed as documented in `m2/README.md`):

```sh
./m2/start_local_postgres.sh
npm ci --prefix web
npm --prefix web run build
.venv-swiss/bin/python -m m2.web_server enroll   # synthetic username/password; password prompt
OPENBLAS_NUM_THREADS=2 .venv-swiss/bin/python -m m2.web_server serve
# Open http://127.0.0.1:8765 in the local browser.
# Stop with Ctrl-C, then ./m2/stop_local_postgres.sh.
```

The command above builds into served `web/dist` and binds port 8765. It is **not** the isolated test procedure and must not be run against an existing service/archive. For source validation, use `python3 .agents/skills/kat-isolated-validation/scripts/validate.py --profile all --execute`; that runner builds under an owned ignored output directory with disposable fixtures instead. Enrollment and serving each own the PostgreSQL archive exclusively. The UI server binds only `127.0.0.1`; API requests require the exact loopback Host/Origin, a server-side expiring opaque session and CSRF for mutations. Do not proxy or expose it on a LAN. No automatic real-data import or API-key discovery is performed. The browser build must be regenerated before startup after source changes. The owned Docker fixture is ephemeral after stop; retain the independent journal with any older backup. `npm --prefix web run test:browser` starts a disposable synthetic browser test database in the configured **owned** fixture and uses local Chromium on this development machine (override with `KAT_BROWSER_BIN`). If your own fixture/server is already running, tests must instead receive `KAT_ISOLATED_TEST_DSN` for a separate disposable PostgreSQL server and `KAT_BROWSER_TEST_PORT` for a free loopback port; do not run them against your open archive or port 8765. `npm --prefix web run test:browser:siwc` uses a synthetic-only provider transport and intercepts its authorization navigation; it never requires real provider credentials. Screenshots and evaluation artifacts belong under `.local/` only.

**Appearance** in the sidebar offers nine light and nine dark reading palettes, with Reading Room’s forest/ivory as the default. Selection changes only CSS variables in this browser: it does not alter messages, charts, consent, model requests, the PostgreSQL archive or another browser’s preference. The choice persists in localStorage across navigation, reload and sign-out; if storage is unavailable or the saved value is unknown, Reading Room is used. A CSP-hashed, synchronous theme bootstrap in `index.html` prevents a light flash for saved dark palettes without allowing arbitrary inline scripts. Natal, transit and synastry wheels follow the selected screen palette; the original standalone SVG retains its light fallback, PNG follows the screen and an explicit print SVG uses a light rendition. Synthetic browser checks exercise all eighteen palettes, mobile/desktop layouts, keyboard focus, contrast, file-consent continuity, and light SVG exports; these do not constitute live-user acceptance.

This implements the locally approved single-scroll study without importing its synthetic messages or preview controls. ## Local workflows and recovery

The local UI supports password login, name-only people and one birth-details form with one **Generate chart** action. Existing people open on a compact Basic info summary with a separate Charts tab showing the single current natal before any configuration. **Create first chart** or **Edit current chart** opens the same birth editor explicitly; changing tabs or closing the editor preserves its unsaved input while the person stays open. An unknown or provisional birth time remains qualified, and earlier versions and chart files are tucked under secondary History sections. A newly created person opens the first-chart editor without creating a chart until Generate is pressed. The user selects a country/region-disambiguated city from the offline GeoNames `cities5000` snapshot (or explicitly supplies Advanced coordinates and IANA timezone); no birth details leave the machine for place lookup. GeoNames city-centre coordinates and canonical timezone are **reference inputs, not a verified birth location**. The user can separately mark their details provisional, supply an exact local time or say time unknown, and inspect Advanced tropical/Placidus/true-node/orb defaults before generating. Gap hours are rejected and repeated DST hours require an explicit occurrence; unknown time stores its full historical local day and does not invent a full natal chart. The save-and-calculate request creates immutable draft/birth/profile/chart versions atomically and is safe to retry after a lost response; a successful chart is displayed even if refreshing the person list fails. Earlier unverified drafts, explicit birth records, solar-only profiles/charts and conversation references remain accessible in History and via the owner-scoped APIs, without auto-promotion. A person can remain without any calculable chart. Optional PDF/PNG/JPEG/WebP references remain separate; storing a file never parses it into a calculated chart. Natal charts require an exact supplied birth time and coordinates (either reference city-centre or manual) for houses; they include ten planets, a selected north node and derived south antipode, Placidus or whole-sign cusps, angles, major aspects, accessible tables and an original downloadable SVG wheel. The SVG itself carries a screen-reader description of its abbreviated labels; a nearby keyboard-openable chart legend maps symbols, rings and numbered rays to words. Color alone never defines a fact. Uncertain time and missing/unsupported houses remain visibly partial, never guessed. This is calculated geometry, not a verified birth-time, interpretation or compatibility reading. See [`m2/NATAL-CHART.md`](../m2/NATAL-CHART.md) for exact conventions and licensing. New person discussions use the owner-scoped active generated natal at turn acknowledgement, including when the profile refresh failed. Historical versions remain visible but are never auto-selected or promoted for new sends. **Discuss current natal** opens a new scoped discussion without sending a model request; the global New conversation remains general. The backend archives the selected version and supplies its bounded, attributed chart facts to the model or returns a terminal context-budget error instead of silently omitting it. A conversation can be general, about one person or shared by several people as **one** archived thread; the sidebar filters by linked person and searches without putting free-text terms in a URL.

**Create chart** is the single desktop/mobile navigation entry. It groups all thirteen approved choices by intention: Personal charts (Natal, Child’s natal), Relationships (Synastry, Composite and Davison), and Timing (Transits, solar/lunar/planetary returns, Midheaven contacts, secondary progressions, true solar arc, progressed lunar phases, and actual lunations/eclipses). Natal/Child chooses or creates a person, then opens the same compact birth editor; Child’s natal is the identical numerical natal method with a temporary family-focused explanation, never a distinct child record, paid interpretation, diagnosis or personality label. Transits opens the existing read-only sky/natal comparison. Synastry chooses two distinct people, resolves each owner-scoped active generated natal at calculation time and shows two separately labelled position rings plus up to 12 closest actual inter-chart longitude aspects with an honest total/omission count. It shares `m2/synastry.py` with agent reads, requires exact supplied birth instants, current sources and compatible zodiac/orb/ephemeris settings, and labels directional planet-in-recipient-house overlays only where the saved recipient houses support them; it never invents unsupported houses, a composite or relationship score. Missing charts offer the existing generation flow, not a file upload or older version selector. Browsing these routes does not create an inference turn, discard an unsent message or silently attach the view; an explicit discussion of the two people starts a new scoped conversation and resolves the then-current charts when a message is sent. Advanced techniques retain their distinct numerical [method contracts](../m2/ADVANCED-TECHNIQUES.md), exact/source-qualified facts, and accessible secondary tables. Return forms default to the saved birthplace; changing place can use a disambiguated offline city centre or explicit coordinates. Solar returns show the selected UTC anniversary bounds and all zero/one/multiple crossings rather than forcing one per year. Result headings receive focus after a deliberate Calculate/open action; a missing exact natal offers a Create/review return path without inventing birth time. Historical results retain their original source and are not silently recalculated. Manual calculation, disclosure and export never send a model message. These checks are synthetic local proof, not live-user interpretation.

**Sky at a date · optional** is a read-only sidebar companion to chat. Enter a date and Copenhagen clock time; only a genuinely repeated hour reveals the earlier/later choice. A nonexistent hour is rejected. Sky only shows planetary positions, actual motion and up to twelve closest same-sky aspects without houses or a birth assumption. Natal + transits resolves the chosen person's active generated exact-time natal on the server; no historical chart-version choice is accepted; distinct colored rings and separate same-sky versus transit-to-natal aspect tables use that chart’s orb policy, expose counts of omitted aspects, and suppress unsupported natal positions/angles. Changing mode/date/person clears old results and never sends a model request, writes chart data or discards the chat composer draft. Return to conversation to discuss the view manually; no button silently attaches a result or sends a message. The real HTTP and desktop/mobile paths are tested only against synthetic data and isolated builds. **Use Now / Today** reads the authenticated application clock and fills the current Copenhagen date/time (plus the DST occurrence if needed), without calculating or sending; click Show to calculate. The clock is not NTP-verified and the zone is not verified location. Each sent turn archives its current UTC instant and Copenhagen reporting date before model input; retries keep the first observation. A model may request the same full chart calculation through a bounded read; its complete result is archived in an openable chart card beside that turn and reopens without recalculation in the conversation view. Sky-only needs no natal; manual transit comparison uses the current generated natal, while conversation reads use the immutable chart recorded for that turn. This never silently attaches a manual view or sends model text.

Each turn preserves its own selected person/draft/chart versions independently of later selections. The selected person's exact draft version (birth date, local time, birthplace or time-unknown flag) is available to the model as **UNVERIFIED user-supplied detail**, not a resolved timezone, UTC instant or calculated chart. A supplied validated birth record is distinct from an unverified draft and is included only when its saved Sun-only or natal computed chart version is explicitly selected. Updating the draft invalidates dependent current-history/search derivatives; historical originals remain in the archive. To continue without old draft-derived answers, start a new thread or correct the old turn explicitly. Browser chat uses only the fixed, connected ChatGPT-plan model; the Qwen fixture remains available for separate local/CLI tests. Enter sends from the Reading Room composer (including touch keyboards); Shift+Enter adds a line, while IME composition is not submitted. Browser chat archives the original input before acknowledging it, and delivers only committed event chunks over a reconnectable cursor. Disconnects and retries never rerun the same turn; a terminal error preserves committed content and offers an explicit new attempt beneath the saved message without replacing a later draft. An original-preserving correction, edit/regenerate, branch selection, bounded history/event pages and private JSONL export are available. Original tool/context events remain in the private archive and JSONL export; ordinary chat does not expose diagnostic event traces. Assistant replies alone render semantic Markdown (including common GFM lists/tables) with inert raw HTML and images, clickable external HTTPS links only, and contained wide code/tables; user input, archived originals and exact event JSON remain literal. Model-backed new turns now record the exact version/mode/digest of a stable product instruction (see [`m2/prompting.py`](../m2/prompting.py)), separate from the selected turn's untrusted evidence. Its local/hosted forms request useful-depth, source-aware conversation without the previous blanket two-sentence restriction. The separate tiny local Qwen fixture and its 128-token reply reserve remain an experimental quality limit: one synthetic chart-overview observation repeated generic text and ended at the limit; the prompt is no proof of good interpretation. No approved real interpretive library, arbitrary/write tools, persistent image permission or all-history memory is implied.

Completed conversation turns can explicitly **Save passage** for a chosen person: select exact user or assistant wording (at most 512 bytes) and optionally write a personal note. The person's **Insights** tab shows source attribution and current/historical status, supports editing the note or removing the saved passage, and opens the original discussion. The original message is never edited. Saved excerpts are labelled as passages, not user assertions, verified facts, chart calculations, or automatically inferred memory. Current-source passages alone may appear in the existing bounded personal-context read; corrected, withdrawn or inactive-branch sources remain visible as historical notebook entries but leave current recall. Saving never calls a model. Source deletion follows the existing archive deletion rules. The owner-scoped notebook is paginated and has only been exercised against synthetic local fixtures.

### Local saved timing, discussion and notes

The person Basic info page offers opt-in **Where am I now?** exploration of saved results only: choose the current natal or a historical source, a UTC start date and an interval. Rows are dated saved calculations with source/method labels, not predictions or a complete scan. Open the exact saved return (including its wheel when present), or choose a particular saved crossing for **Discuss this result**; the selected identity is attached to the new discussion only after an explicit send. Return calculation pages also offer a per-crossing Discuss action. Changing the draft or dismissing selection does not send anything.

**Saved for later** contains only manually saved items; optional local in-app reminders never send external notifications or automatically start model calls. **Private event journal** holds deliberately entered date-only, uncertain-date or validated local-time reflections, optionally linked to a saved item. Journal text is not model context, a tool result or automatic recall. The on-demand chart-term glossary explains geometry versus interpretation, including MC, return, aspects, transits, progressions and derived relationship methods. Bundled chart fonts load as same-origin WOFF resources under the ordinary CSP; standalone SVG/PNG/print exports embed their own subset fonts in the detached export only. Browser synthetic evidence verifies no page CSP font/style violation and legible exported glyphs. No deployment or served build is part of this source work.

## Conversation title provenance and historical backfill

After a new browser thread receives a substantive completed first question, a separate, tool-free, one-attempt title request uses the same fixed eligible ChatGPT-plan model. The input is one redacted question capped at 600 characters, never the archive or chart files; the response is capped at 80 output tokens and checked for a short, non-identifying topic. Greeting-only turns wait for a substantive question. The completed turn is independent of title failure. A provider failure leaves the visible placeholder and records a `failed` provenance status in the owner-scoped API; reconnect and replay do not repeat the request. Owner, active-turn, revision and manual-rename checks fence the delayed result. Search and the sidebar receive updated titles after local refresh, without modifying turn content.

Old titles retain `legacy` provenance, including potentially intentional “New conversation” names. The internal `TitleWork.backfill_candidates` provides an owner-scoped, 20-item, read-only preview of ambiguous machine-prefix candidates. Only explicit per-ID selection can promote one for title work; this implementation does **not** activate the historical batch, expose an automatic browser action, send private archive prompts to the provider, or claim older threads have been retitled. Backfilling real historical content requires your separate one-time, specifically scoped approval and the actual provider permission; synthetic tests do not establish that access.

## Optional provider boundary (not live-validated)

The browser is fixed to server-selected `gpt-6.1-sol` on the direct ChatGPT-plan Responses route and `Europe/Copenhagen` for reporting dates. There is no client model, local fallback, upload or composer-zone selector for new sends. If plan permission or this exact model is unavailable, sending fails before archiving a turn with a recoverable draft and a connection action; it never silently switches billing or models. New conversation turns/edit/regeneration send only person IDs; at durable acknowledgement the server attaches each person's single current generated natal if one exists. A new Generate action updates that current pointer and leaves immutable birth/chart/turn history intact; replay of an older request ID does not roll the current natal back. Schema 016 backfills latest recorded generated chart per owner/person, never guessing from legacy/solar versions. Historical turns and their owner-scoped attachments remain readable, exportable and exactly replayable; upload ingress is closed. Copenhagen is a reporting default, **not** a birth-time zone or a verified current location.

The optional **Sign in with ChatGPT** integration is implemented behind the default-off `KAT_ENABLE_SIWC` gate. Agent validation covers signed-ID-token, fake HTTP/SSE and synthetic native form/callback fixtures only. The user reports successful live conversations, but this is not an agent-verified plan grant, provider capability or response-quality assessment. A read-only observed catalog field is capacity metadata, not an inference or eligibility check. When separately authorized and enabled, the backend uses official dynamic OSS registration, host ID, one-time state/nonce/PKCE, validated OpenAI ID tokens, separately granted `chatgpt.tokens.use.direct`, account-scoped rotating credentials stored in owner-only files, account-specific model discovery and direct `POST /v1/responses` with `store:false`, `stream:true`. The browser receives neither provider tokens nor the callback code, and no hosted MCP/provider history is used. Plan authorization remains explicit at connection time; provider errors do not silently switch billing or retry inference. Existing file-backed turns retain their original attachment digest/consent and immutable archived evidence, but no new browser turn/edit/regeneration can send a file. Previously stored references can still be read and deleted when no archived turn references them; a refused Delete returns an owner-scoped 409 and shows dependent conversations. Browsing a referenced conversation is not consent to delete it. Historical file content may include private metadata or untrusted instructions. The retained provider media adapter only supports historical replay/other explicitly authorized entry points; it is not a browser upload route. Sources: [documented model inputs](https://developers.openai.com/api/docs/models/gpt-6.1-sol), [image input](https://developers.openai.com/api/docs/guides/images-vision), [inline PDF input](https://developers.openai.com/api/docs/guides/file-inputs). Eligibility is determined by OpenAI policy and the selected account, not by this local implementation. Sources: [OSS sign-in](https://developers.openai.com/siwc/token-sharing-open-source/sign-in), [Responses inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference), [preview limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations) and [errors/recovery](https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery). Do not enable the flag or enter actual provider credentials as part of this synthetic-only validation.

A complete selected natal chart and a normal paragraph fit both the synthetic context-only 500k catalog shape and the source-documented `gpt-6.1-sol` API text window under Kat's **estimated** preflight accounting; synthetic browser-to-fake-Responses tests also cover a local too-small window, explicit model change and retained archived error/input. A selected local chart may exceed the actual Qwen test window even with `hi`; the composer warns, the archived error states the model limit and Kat never auto-selects hosted use. Hosted catalog context and maximum-output extensions are validated independently when present; the public Models API need not supply either. A catalog-advertised 500k context with no maximum-output field retains that 500k context; only the missing output ceiling uses the named model's API documentation fallback, clearly labelled separately in archived context. Neither a documented fallback nor a text estimate verifies real-plan inference/output eligibility or quality. Other model slugs without both bounds fail without inference; no live model/usage/cost verification was attempted. See [`m2/README.md`](../m2/README.md) for budget provenance and calculation limits.

Model-directed chart, source, transit and history reads have **no fixed conversational round or provider-request count**: each valid native result commits before the next model request, and the model decides when to answer. Owner permissions, read arguments, per-result and aggregate evidence bytes, context/reply capacity, cancellation and replay still guard each step. Duplicate native call IDs, invalid provider output, archive refusal, incomplete results that cannot fit context and empty answers fail distinctly rather than being called normal read exhaustion. Local fake HTTP/SSE and browser fixtures exercise later rounds and completion; no further live exchange was run.

Long hosted conversations use a proactive **derived** summary of older eligible active-branch turns when the projected next request approaches the selected model's window. The UI shows a committed “Summarizing older eligible turns” state and a checkpoint/usage evidence entry; recent exact turns and the current question stay verbatim, and selected saved chart facts come from their authoritative archive versions, not a summary. Model-written summaries can omit nuance or make mistakes; neither a checkpoint nor an old image is a new source or a fresh file-consent grant. A failed/incomplete/aborted summary leaves the previous checkpoint and originals intact, archives an error and restores the draft; no failed turn runs automatically. Select a supported model explicitly and create a **new** turn if you want to retry. This has only been exercised with synthetic provider responses and is not a claim of real-plan availability or semantic memory quality. See [`m2/README.md`](../m2/README.md) for capacity, summary provenance, count uncertainty and source fences.

## Deletion, backup and limits

The browser offers per-person reference-file deletion, owner-scoped conversation export, and explicit journalled conversation/person deletion. A person with any related conversation remains undeletable until the conversation is removed; source-linked dependent conversations must be handled under the backend dependency rules before deletion. Exports and separately saved files are not revoked by deleting the managed archive. For full owned PostgreSQL/file backups and restores, use the documented local CLI/backup procedures in [`m2/README.md`](../m2/README.md) while the owned fixture remains available; stopping its ephemeral Docker instance without a backup discards its database. The original mockup is a visual reference, not a source of messages or accounts. Test-model reply quality, interpretive accuracy, provider eligibility and real-data policy require separate human evaluation; green local checks are not acceptance.
