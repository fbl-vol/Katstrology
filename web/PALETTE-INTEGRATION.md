# Eighteen reading palettes

`kat-eight-palette-additions-1` approves all eight concepts in `mockups/theme-study/palettes.json` as **additions**: Peony, Wisteria, Apricot Silk, Sea Pearl, Black Cherry, Moonstone, Cocoa Rose and Midnight Orchid. They join the ten original themes. Rosewood, Aubergine, every existing theme ID/value, the Reading Room default, and `kat.appearance.theme` preference key remain unchanged. Existing stored IDs still select the same theme. An unknown ID or inaccessible storage falls back to Reading Room before the app paints.

The concepts provide base colors, not a full product stylesheet. Their `paper`, `panel`, `ink`, `muted`, `sidebar`, `side-ink`, `side-muted`, `accent`, `on-accent`, `tint` and `line` values map to the corresponding `themes.css` semantic roles. The product-specific sidebar controls, focus, surfaces, field, links, warnings/errors/success and overlay roles are chosen separately for legibility; all are explicit per theme. `themes.ts` lists the IDs and descriptions, `themes.css` supplies screen and swatch colors, and the CSP-pinned `index.html` prepaint script contains the same allowlist. The fixed CSP hash in `m2/web_server.py` must change whenever that inline script changes.

`web/tests/theme-contract.spec.ts` guards all eighteen explicit token blocks and prepaint IDs, pins the ten original token sets, and checks the retained default. `appearance.spec.ts` checks per-theme contrast, persistence, keyboard use and browser presentation-only behavior. Chart screen SVG and PNG use selected colors; the original standalone SVG remains light and the separate print-ready SVG uses white paper. Validate actual desktop/mobile/short/ultrawide product screens, forms, notebook, errors, focus and rendered exports before delivery. Static mockup contrast and fictional layouts are references, not product acceptance. No new activation, real account, provider call, or deployment follows from local integration.
