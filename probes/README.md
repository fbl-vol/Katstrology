# M1 local feasibility probes

These are disposable, **local synthetic-only** experiments, not a hosted app or
production calculation API. The supplied personal chart and conversation, `PLAN.md`,
`session.txt`, original research report and all outputs stay under the local-only
workspace. Do not add them, private ephemeris inputs or generated archives to Git.
The detailed original M1 research report is preserved locally at
`.local/probes-m1-research-original-before-public-boundary.md`; it is not a
public oracle and must not be published.

## Reproduce without a personal chart

Use CPython 3.11.16 and the pinned public packages. From the checkout root:

```bash
umask 077
uv venv --seed --python 3.11.16 .venv-swiss
uv pip install --python .venv-swiss/bin/python -r probes/requirements-swiss.txt
# Download only public Swiss ephemeris files, verify their hashes below, and
# place them under .local/ephe/; no personal input goes into the download.
PYTHONDONTWRITEBYTECODE=1 OPENBLAS_NUM_THREADS=2 \
  .venv-swiss/bin/python -m unittest discover -s probes -v
```

The optional private-image comparison is skipped if `.local/chart-reference.json`
is absent. Alternatively set `KAT_CHART_REFERENCE` to an existing **local** JSON
reference you supplied yourself; an explicitly configured missing file is an
error, not a silent skip. This repository does not provide a birth-chart oracle
or an individual's birth data. The independently worked public solar and
capture tests still need the public Swiss files. Do not infer that a green run
without a private fixture validates image agreement.

For an existing, separately supplied private chart fixture only:

```bash
KAT_CHART_REFERENCE=.local/chart-reference.json \
  PYTHONDONTWRITEBYTECODE=1 OPENBLAS_NUM_THREADS=2 \
  .venv-swiss/bin/python -m unittest discover -s probes -v
.venv-swiss/bin/python probes/chart_probe.py .local/chart-reference.json \
  > .local/chart-results.json
```

The expected private JSON is consumed by `chart_probe.py`, not generated by this
repository. Its `local_datetime`, `timezone`, `expected_utc`, latitude/longitude,
image-transcribed body/cusp positions and sidereal time must be supplied and
checked against the source image outside this repository. The script rejects
time-zone/UTC disagreement and Swiss-file fallback, and compares 12 body/point
positions plus six cusps. Its declared tolerances are **2 arcseconds** for
body/point values and **60 arcseconds** for minute-only cusps. It also samples
±5 minutes around the supplied time; those samples are conditional sensitivity,
not verified time uncertainty or interval extrema. No birth time or chart result
is included in the public repository. Original comparison deltas and related
research evidence remain local only.

## Public local tokenizer fixture

The complete backend suite includes five real local-tokenizer context-budget tests.
They require the native binding and GGUF even though hosted browser startup does
not. In a pip-enabled CPython3.11 virtualenv on Linux x86_64, prepare both with:

```bash
.venv-swiss/bin/python -m deploy.prepare_test_model
```

This installs `probes/requirements-model.txt` with the official llama-cpp-python
0.3.36 CPU wheel pinned by SHA-256, and downloads the public
[Qwen GGUF](https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct-GGUF/tree/9217f5db79a29953eb74d5343926648285ec7e67)
`qwen2.5-0.5b-instruct-q5_k_m.gguf`: 522186592 bytes, SHA-256
`041474553fcabfc2a2d67903f9d2c2e50bd92528e670da4f33b5d0ce6e59fd55`.
Cold downloads and existing cache entries must match; corrupt files fail rather
than being silently replaced. No model inference, provider call or private cache
is used. This fixture is test-only, not included in the production image/artifacts.
CI's existing `deploy.prepare_ci_inputs` entry point prepares it after Swiss files.

## Scope and independently checkable methods

`chart_probe.py` uses tropical, geocentric apparent positions, Placidus houses,
true node and Gregorian dates. Swiss leap-second/delta-T handling converts UTC
to UT1/TT; every body must report `FLG_SWIEPH`, not an unnoticed Moshier
fallback. Its independently supplied private image remains authoritative only
when the optional local fixture is configured. One chart is not universal
astrology compatibility.

`core_calc.py` re-exports the production `m2/core_calc.py` contract for the retained M1 probes. It supports **solar-only** tropical geocentric longitude, supplied
UTC uncertainty endpoints up to 24 hours, ecliptic longitude aspect *geometry*
(no orb policy), and bounded forward solar transit crossings against a fixed
natal longitude. It brackets crossings to 60 seconds within windows of at most
30 days, supports UTC years 1900–2099, and rejects unresolved named-zone DST
folds/gaps. It does not implement unknown-time houses, Moon interval extrema,
retrograde/station searches, generic planet/aspect or MC-prognosis equivalence.
A public [USNO 2024 season table](https://aa.usno.navy.mil/calculated/seasons?dst=false&submit=Get+Data&tz=0&tz_label=true&tz_sign=0&year=2024)
reports the March equinox at 03:06 UT (minute resolution); tests require the
solar zero-degree crossing within three minutes, not universal accuracy.

`capture_probe.py` is a disposable SQLite ordering experiment: input commits
before scripted source invocation; generated events commit before delivery;
retries replay without reinvocation; failed writes do not deliver unsaved chunks;
startup marks abandoned turns interrupted. Older local archives are **readable**
after a nullable-parent schema upgrade. This does not prove PostgreSQL or remote
provider durability. `conversation_probe.py` adds bounded selected-branch context,
explicit gateway-selected solar tool capture and local token budgeting, not a
supported external client. `local_model_probe.py` and
`integrated_model_probe.py` optionally use a small in-process CPU Qwen fixture;
its answers are plumbing observations, not product-quality dialogue. Model
request/capture outputs stay in `.local/` and must remain synthetic.

The M1 engineering recommendation is a Python backend-owned event gateway with
one narrow direct Swiss calculation boundary. Open WebUI filter hooks do not
establish full archive capture; Kerykeion selection does not establish the Swiss
backend. Wider astrology methods, real data, external-client capture, licensing
and production readiness remain separate decisions. Swiss Ephemeris and
pyswisseph have AGPL/professional-license boundaries; no distribution terms are
approved by local testing. Relevant first-party or project references include
[Swiss licensing](https://www.astro.com/swisseph/swephinfo_e.htm),
[pyswisseph licensing](https://raw.githubusercontent.com/astrorigin/pyswisseph/master/LICENSE.txt),
[Kerykeion configuration](https://kerykeion.net/python-library/docs/v6/swisseph_configuration)
and [Open WebUI Filter hooks](https://docs.openwebui.com/features/extensibility/plugin/functions/filter/).
